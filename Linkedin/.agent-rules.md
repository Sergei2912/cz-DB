# Agent Rules — LinkedIn Career Architect

> Injected into every Agent Orchestrator session via `agentRulesFile`.
> Canonical source for all agent behavior rules in this project.

## 1. Project Context

LinkedIn profile optimization system for **Dr. Sergii Anipreyev (DMD)** — endodontist targeting the **Israeli healthcare market**.

- **Architecture:** 8 agents + 4 recruiter personas
- **Databases:** 13 Notion DBs (7 Universita Hub input + 6 LinkedIn Optimizer output)
- **Commands:** 29 skill commands + 3 compound workflows
- **Data config:** `data/profile-context.yaml` (keywords, pillars, templates, rhythm)
- **Persona:** Primary — Maya Cohen (Senior Healthcare Recruiter); additional — Yael Levy, David Stern, Anna Petrova

## 2. Configuration Hierarchy

```
profile-context.yaml  — data (IDs, keywords, pillars, schedule)
.agent-rules.md       — rules (safety, quality, Notion patterns)
CLAUDE.md             — summary reference (quick-start, architecture)
agents/*.md           — domain logic (agent-specific behavior)

On conflict: .agent-rules.md wins over CLAUDE.md;
profile-context.yaml wins over hardcoded values in agent files.
```

All database IDs are centralized in `data/profile-context.yaml` § `data_sources`. Agent files reference YAML by path — never hardcode IDs in agent specs. CLAUDE.md and .agent-rules.md keep IDs as a human-readable reference only.

- Trailing newlines in all files

- Break complex tasks into steps; show progress

## 5. Safety Rules

1. **Browser: full read-write access** via Chrome extension (Claude in Chrome) and Playwright MCP. LinkedIn modifications (edit, save, post, send) require **explicit user confirmation** before execution.
2. **All content is DRAFT** — user reviews and publishes manually. Never publish directly.
3. **Never enter credentials** — if login is needed, ask the user to handle it.
4. **Never automate** connection requests, messages, or posts **without user approval**. Always present draft and wait for confirmation.
5. **All metrics and credentials from Notion** — never hardcode data, always fetch live from Universita Hub.
6. **LinkedIn Ready flag** — only use Skills/CV Items where `LinkedIn Ready = true`.
7. **Medical vocabulary** — use terms from Medical Lexicon DB (Strength = "High"; "Medium" for variety). Never use Avoid-flagged or "Low" terms.
8. **Recruiter persona = advisory** — enriches other agents' output, does not replace them.
9. **Competitor analysis = READ-ONLY** — never interact with, follow, or message competitor profiles.

## 6. Content Standards

- **Voice:** Professional, authoritative, grounded in clinical experience. No generic motivational language.
- **Content pillars:** Clinical Cases, IDF Transition, European Perspective, Tech in Dentistry, Russian Patients, General.
- **ATS priority keywords (EN):** endodontist, root canal treatment, surgical microscope, IDF Medical Corps, DMD, CBCT, NiTi rotary files.
- **ATS priority keywords (HE):** אנדודונט, טיפול שורש, מיקרוסקופ כירורגי, חיל רפואה, רופא שיניים.
- **Hashtags:** 3-5 per post (2 EN primary + 1-2 EN secondary + 1 HE). Add 1 niche hashtag matching the pillar.
- **A/B testing:** Generate 3 variants for headlines; 2 variants for posts. Track via Content Bank `AB_Group` property.
- **Posting schedule:** Sunday + Thursday optimal. Avoid Friday/Saturday (Shabbat). Best times: 08:00-09:00, 12:00-13:00, 18:00-19:00 IST.

### Critical Query Patterns

- **Writes** — always use `data_source_id` (NOT `database_id`)
- **Content Bank title property** — `"Title"` (NOT `"Name"`)
- **Select values are case-sensitive** — `"Draft"`, `"Post"`, `"Clinical Cases"`
- **Universita reads** — use `data_source_url: "collection://<id>"` with `notion-search`
- **Never use `notion-fetch` with `collection://`** — it returns schema, not records

## 8. Browser Access Rules

Full read-write access to LinkedIn is available through:
- **Chrome MCP** (Claude in Chrome extension): `computer`, `form_input`, `find`, `read_page`, `navigate`
- **Playwright MCP**: `browser_click`, `browser_type`, `browser_fill_form`, `browser_navigate`, `browser_snapshot`

**Allowed without confirmation:** navigate, read, snapshot, screenshot, evaluate, scroll.
**Require user confirmation:** click (interactive elements), type/fill (form inputs), submit, post, send, connect.

**Never do (even with confirmation):**
- Enter passwords or credentials
- Accept terms or agreements
- Make purchases or payments
- Download files from LinkedIn

## 9. Medical Vocabulary Rules

Source: Medical Lexicon DB (`acae23d9-42dd-4d0c-9a16-e9e88220805b`) — 58 records.

- Use terms with **Strength = "High"** (validated clinical terminology). "Medium" acceptable for variety; never use "Low".
- **Never** use terms flagged as `Avoid` in the Lexicon
- Hebrew medical terms: always use the Hebrew column from Lexicon, never auto-translate
- When introducing a clinical term, provide both EN and HE: `"root canal treatment (טיפול שורש)"`
- Run Medical Vocabulary Checker subagent after generating clinical content
